1. Lab Objectives

Deploying infrastructure and code is only half the engineering lifecycle. Operating financial platforms requires end-to-end smoke verification, rigorous ledger balance audits, log aggregation, and battle-tested disaster recovery protocols.

In this final capstone lab, you will achieve the following milestones:

  • Execute End-to-End Smoke Verification: Validate the frontend UI, backend REST API, and Swagger OpenAPI specification across public AWS endpoints.
  • Audit Ledger Mathematical Invariants: Execute a double-entry transaction and verify that $\sum \text{Debits} == \sum \text{Credits}$ holds under concurrent load.
  • Master Production Observability: Stream structured container logs, query health state metadata, and diagnose silent container failures.
  • Conduct a Full Disaster Recovery Drill: Simulate complete compute instance loss, re-provision infrastructure with Terraform, re-configure host with Ansible, and restore PostgreSQL state from an S3 cold backup in under 15 minutes.

3. Ledger Transaction Integrity Audit

Execute an authenticated double-entry financial transaction and verify ledger equilibrium:

terminal — test financial transaction & balance check
BASH
# 1. Obtain JWT Bearer Token
JWT_TOKEN=$(curl -s -X POST "http://${HOST_IP}:3001/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@zeetafin.com","password":"AdminProductionPassword123!"}' \
  | jq -r .access_token)

# 2. Post a Double-Entry Ledger Entry: Debit Cash ($2,500), Credit Revenue ($2,500)
curl -s -X POST "http://${HOST_IP}:3001/api/transactions" \
  -H "Authorization: Bearer $JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "reference": "INV-2026-001",
    "description": "Enterprise Platform License Payment",
    "entries": [
      {"account_code": "1010", "type": "DEBIT", "amount": 2500.00},
      {"account_code": "4010", "type": "CREDIT", "amount": 2500.00}
    ]
  }' | jq .

# 3. Verify Ledger Balance Assertion inside PostgreSQL: Sum(Debits) - Sum(Credits) == 0
ssh -i ~/.ssh/zeetafin-key ubuntu@$HOST_IP \
  "docker exec zeetafin-db psql -U zeetafin_user -d zeetafin_db -c \
  'SELECT SUM(CASE WHEN type = '\''DEBIT'\'' THEN amount ELSE -amount END) AS balance_diff FROM ledger_entries;'"
# Expected: 0.0000 (Mathematical Equilibrium Guaranteed!)

5. Disaster Recovery Architecture (RTO < 15m, RPO < 24h)

Failure Tier Failure Scenario Operational Recovery Protocol Target RTO
Tier 1: Bad Release Container crash-loops upon new deployment Automated SHA rollback triggered by dual-vantage health failure < 30 seconds
Tier 2: Node Failure EC2 hardware impairment or host kernel crash AWS EC2 Auto-Recovery or Terraform re-apply + Ansible < 8 minutes
Tier 3: Total AZ Outage AWS Availability Zone disruption or volume corruption Terraform apply in new AZ + restore PostgreSQL dump from S3 < 15 minutes

6. Full Disaster Recovery Drill

terminal — full disaster recovery simulation
BASH
# PHASE 1: Create transactional PostgreSQL backup
ssh -i ~/.ssh/zeetafin-key ubuntu@$HOST_IP <<EOF
  docker exec zeetafin-db pg_dump -U zeetafin_user -Fc zeetafin_db > /tmp/zeetafin_db_backup.dump
  aws s3 cp /tmp/zeetafin_db_backup.dump s3://zeetafin-backups-production/latest.dump
EOF

# PHASE 2: Simulate total host loss (Destroy EC2 compute instance via Terraform)
cd infra/terraform
terraform destroy -target=aws_instance.app_server -auto-approve

# PHASE 3: Re-provision infrastructure with Terraform
terraform apply -auto-approve
NEW_HOST_IP=$(terraform output -raw ec2_public_ip)

# PHASE 4: Re-configure Docker Engine with Ansible
cd ../ansible
ansible-playbook playbook.yml

# PHASE 5: Launch containers and restore PostgreSQL data from S3
ssh -i ~/.ssh/zeetafin-key ubuntu@$NEW_HOST_IP <<EOF
  git clone https://github.com/Devzane/zeetafin-platform.git
  cd zeetafin-platform
  aws s3 cp s3://zeetafin-backups-production/latest.dump /tmp/restore.dump
  docker compose -f deploy/docker-compose.prod.yml up -d db
  docker exec -i zeetafin-db pg_restore -U zeetafin_user -d zeetafin_db -c < /tmp/restore.dump
  docker compose -f deploy/docker-compose.prod.yml up -d
  curl -s http://localhost:3001/api/health
EOF

# Platform 100% recovered with zero data loss in under 12 minutes!

7. Zero-Downtime Secret Rotation

When rotating IAM keys, database master passwords, or JWT secrets:

  1. Update secret in GitHub Repository Secrets.
  2. Generate new credentials in PostgreSQL using ALTER USER zeetafin_user WITH PASSWORD 'new_pass';
  3. Update production host .env file.
  4. Execute in-place rolling swap via docker compose up -d. Zero dropped TCP connections.
