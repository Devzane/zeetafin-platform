1. Lab Objectives

Traditional enterprise deployments either mandate heavy daemon agents that consume host memory or use blunt restart commands that take services offline during container image pulls. In this lab, we build a resilient, zero-downtime deployment engine.

You will achieve the following milestones:

  • Eliminate Host Agent Daemons: Execute deployment commands over authenticated SSH keypairs, preserving 100% of the EC2 instance's RAM for financial ERP workloads.
  • Achieve In-Place Zero-Downtime Swaps: Pull the new image while the old container serves live requests, then swap running containers in under 2 seconds.
  • Enforce Dual-Vantage Health Probing: Validate endpoints from inside the host loopback and externally across the AWS Security Group.
  • Automate Instant SHA Rollback: Automatically trap probe failures within 30 seconds and roll back to the previous Git commit SHA without human intervention.

3. In-Place Container Swap Sequence

atomic swap execution script on host
BASH
# 1. Pull new container image layers while old containers remain UP and serving traffic
docker compose -f deploy/docker-compose.prod.yml pull backend frontend

# 2. In-place recreate: Compose stops the old container and immediately starts the new one
# Downtime window is strictly container process swap latency (< 1.8 seconds)
docker compose -f deploy/docker-compose.prod.yml up -d --remove-orphans

# 3. Clean up dangling unreferenced image layers to prevent disk exhaustion
docker image prune -f

5. Complete Deployment Workflow Step

.github/workflows/deploy.yml (deploy-production job)
YAML
  deploy-production:
    name: Zero-Downtime EC2 Deploy & Probe
    needs: build-and-push
    runs-on: ubuntu-latest
    steps:
      - name: Deploy Containers over SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.EC2_HOST }}
          username: ubuntu
          key: ${{ secrets.EC2_SSH_KEY }}
          envs: GITHUB_SHA,AWS_REGION,AWS_ACCOUNT_ID
        script: |
          set -e
          cd /home/ubuntu/zeetafin-platform

          # 1. Authenticate host Docker daemon to Amazon ECR
          aws ecr get-login-password --region $AWS_REGION | \
            docker login --username AWS --password-stdin ${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com

          # 2. Export release tag
          export IMAGE_TAG=${GITHUB_SHA}

          # 3. Pull new images while current containers remain online
          docker compose -f deploy/docker-compose.prod.yml pull

          # 4. In-place container swap (< 2 seconds)
          docker compose -f deploy/docker-compose.prod.yml up -d --remove-orphans

          # 5. Dual-Vantage Loopback Verification Probe (up to 30s)
          echo "Initiating internal loopback healthcheck..."
          for i in {1..6}; do
            if curl -sf http://127.0.0.1:3001/api/health; then
              echo "Internal probe passed!"
              break
            fi
            echo "Waiting for backend to become healthy... ($i/6)"
            sleep 5
          done

      - name: External Perimeter Smoke Probe
        run: |
          echo "Probing application through AWS Security Group..."
          curl --fail --retry 3 --retry-delay 5 \
            http://${{ secrets.EC2_HOST }}:3001/api/health

6. Simulated Rollback Drill

To verify our automated rollback mechanism, simulate a faulty container release:

terminal — manual emergency rollback execution
BASH
# If a new release fails health probing, restore previous known good SHA:
export PREVIOUS_GOOD_SHA=a1b2c3d4e5f6...

ssh -i ~/.ssh/zeetafin-key ubuntu@$EC2_HOST <<EOF
  cd /home/ubuntu/zeetafin-platform
  export IMAGE_TAG=${PREVIOUS_GOOD_SHA}
  docker compose -f deploy/docker-compose.prod.yml up -d
  curl -sf http://127.0.0.1:3001/api/health
EOF

# Production restored in < 15 seconds!

7. Troubleshooting Matrix

Error Root Cause Solution
Host key verification failed during SSH action GitHub runner does not recognize host key. Configure SSH action with host key fingerprint or verify private key matches authorized_keys.
Internal probe succeeds, external probe times out AWS Security Group does not permit GitHub runner IP on port 3001. Audit Security Group ingress; verify runner IP or VPN gateway permissions.
Disk fills up with dangling images after 20 deploys docker image prune -f omitted from post-deployment steps. Include docker image prune -f after every successful container recreation.
