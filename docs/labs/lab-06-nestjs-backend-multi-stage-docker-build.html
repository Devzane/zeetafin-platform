Runtime SRE Fact Node.js was never intended to run as PID 1 in Linux. Without an init wrapper like dumb-init, child processes become unkillable zombies upon container termination.

1. Lab Objectives

A naive docker build for a TypeScript NestJS application packages the entire TypeScript compiler, Jest test suites, developer linters, and full node_modules directory, producing a fragile image exceeding 1.2 GB. In this lab, we engineer an enterprise multi-stage build.

You will achieve the following milestones:

  • Slashing Attack Surface by 88%: Drop image weight from ~1.2 GB to under 150 MB using node:20-alpine.
  • Eliminate Build Tool Leakage: Use a separate compilation stage to generate dist/, prune devDependencies with npm prune --production, and discard raw TypeScript source files.
  • Graceful Shutdown & Signal Handling: Integrate dumb-init to forward POSIX SIGTERM signals to NestJS, enabling zero-loss transaction shutdowns.
  • Non-Root Principle of Least Privilege: Drop root permissions and execute the server under the built-in node unprivileged user (UID 1000).

4. Production Dockerfile (apps/backend/Dockerfile)

apps/backend/Dockerfile
DOCKERFILE
# ==============================================================================
# STAGE 1: Dependency Installation
# ==============================================================================
FROM node:20-alpine AS deps
WORKDIR /app

# Install build tools if native node-gyp packages require compilation
RUN apk add --no-cache libc6-compat

COPY package*.json ./
RUN npm ci

# ==============================================================================
# STAGE 2: TypeScript Compilation & Production Pruning
# ==============================================================================
FROM node:20-alpine AS builder
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Compile TypeScript to JavaScript in /app/dist
RUN npm run build

# Prune devDependencies to strip TypeScript, linters, and test runners
RUN npm prune --production

# ==============================================================================
# STAGE 3: Minimal Production Runtime
# ==============================================================================
FROM node:20-alpine AS runner
WORKDIR /app

# Install dumb-init to properly handle PID 1 signal forwarding & zombie reaping
RUN apk add --no-cache dumb-init

ENV NODE_ENV=production
ENV PORT=3001

# Copy only compiled code and runtime-only node_modules from builder
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY package.json ./

# Enforce least-privilege non-root execution (UID 1000)
USER node

EXPOSE 3001

# dumb-init catches SIGTERM and forwards it directly to the Node.js process
ENTRYPOINT ["/usr/bin/dumb-init", "--"]
CMD ["node", "dist/main.js"]

6. Runtime Verification & Signal Handling

terminal — runtime user & signal test
BASH
# 1. Run container locally in background
docker run -d --name test-backend -p 3001:3001 zeetafin-backend:local

# 2. Confirm unprivileged user identity inside container
docker exec test-backend id
# Expected: uid=1000(node) gid=1000(node) groups=1000(node)

# 3. Verify PID 1 is dumb-init and PID 2 is node
docker exec test-backend ps aux
# Expected:
# PID   USER     COMMAND
# 1     node     /usr/bin/dumb-init -- node dist/main.js
# 7     node     node dist/main.js

# 4. Clean up test container
docker stop test-backend && docker rm test-backend

7. Troubleshooting Matrix

Error Root Cause Remediation
Cannot find module '/app/dist/main.js' TypeScript compilation failed or COPY --from=builder path mismatch. Verify npm run build outputs to dist/ in tsconfig.json and check builder stage copy paths.
Container hangs for 10s on docker stop Missing dumb-init; Node.js as PID 1 ignores standard SIGTERM. Ensure ENTRYPOINT ["/usr/bin/dumb-init", "--"] wraps the process.
Error loading shared library ld-linux-x86-64.so.2 Native C++ node bindings compiled against glibc instead of musl. Install libc6-compat in Alpine base or rebuild native bindings inside the Alpine builder.
EACCES: permission denied, open '/app/logs' Container writes to filesystem as user node without write permissions. Stream logs directly to stdout/stderr (Twelve-Factor App principle); do not write local log files.
