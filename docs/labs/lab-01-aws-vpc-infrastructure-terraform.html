Lab Focus Eliminate default VPC vulnerabilities and manual ClickOps by codifying AWS networking from scratch.

1. Lab Objectives

In production cloud engineering, manual provisioning through the AWS Management Console introduces untracked drift, inconsistent firewalls, and leaky security perimeters. In this hands-on lab, you will build the bedrock network for the ZeetaFin Financial Platform.

By the end of this lab, you will achieve the following production milestones:

  • Eliminate Default VPC Insecurities: Avoid default subnets that map open routes to all Availability Zones with permissive default security groups.
  • Architect Deterministic CIDR Allocation: Carve a private 10.0.0.0/16 supernet and isolate compute into a defined 10.0.1.0/24 subnet (251 usable host IPs).
  • Construct Stateful Perimeter Defense: Lock down inbound SSH (TCP 22), Frontend UI (TCP 3000), and Backend REST API (TCP 3001) strictly to your workstation's /32 IP address.
  • Enforce Reproducible IaC: Pin Terraform core and AWS provider versions to prevent breaking upstream syntax changes in CI/CD pipelines.

3. Prerequisites & Setup

Before launching Terraform, verify toolchain installations and authenticate your AWS CLI environment:

terminal — local environment validation
BASH
# 1. Verify Terraform CLI (v1.5+ required)
terraform -version

# 2. Verify AWS CLI (v2.x required)
aws --version

# 3. Verify AWS credentials and caller identity
aws sts get-caller-identity

# 4. Fetch your current public IP address to bind security rules
curl -s https://checkip.amazonaws.com
Workstation /32 Binding

Binding your security group strictly to your_public_ip/32 ensures that even though the EC2 instance resides in a public subnet, internet port scanners and automated credential crawlers cannot discover or initiate TCP handshakes on ports 22, 3000, or 3001.

5. Terraform Implementation

A. Provider & Version Locking (versions.tf)

infra/terraform/versions.tf
HCL
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region

  default_tags {
    tags = {
      Project     = "ZeetaFin"
      Environment = var.environment
      ManagedBy   = "Terraform"
    }
  }
}

C. Network Resources & Security Group (main.tf)

infra/terraform/main.tf
HCL
# 1. Custom VPC
resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = {
    Name = "zeetafin-vpc-${var.environment}"
  }
}

# 2. Internet Gateway
resource "aws_internet_gateway" "gw" {
  vpc_id = aws_vpc.main.id

  tags = {
    Name = "zeetafin-igw-${var.environment}"
  }
}

# 3. Public Subnet
resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = var.public_subnet_cidr
  availability_zone       = var.availability_zone
  map_public_ip_on_launch = true

  tags = {
    Name = "zeetafin-public-subnet-${var.environment}"
  }
}

# 4. Route Table with Default Internet Egress
resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.gw.id
  }

  tags = {
    Name = "zeetafin-public-rt-${var.environment}"
  }
}

# 5. Subnet Route Table Association
resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

# 6. Hardened Security Group
resource "aws_security_group" "app_sg" {
  name        = "zeetafin-host-sg-${var.environment}"
  description = "Strict least-privilege ingress for SSH and application endpoints"
  vpc_id      = aws_vpc.main.id

  # Ingress: SSH Management (Port 22)
  ingress {
    description = "SSH administrative access from operator IP"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  # Ingress: Next.js Frontend (Port 3000)
  ingress {
    description = "Web UI ingress from operator IP"
    from_port   = 3000
    to_port     = 3000
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  # Ingress: NestJS Backend API (Port 3001)
  ingress {
    description = "REST API ingress from operator IP"
    from_port   = 3001
    to_port     = 3001
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  # Egress: Full Outbound (APT packages, Docker Hub, ECR)
  egress {
    description = "Allow all outbound traffic"
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "zeetafin-sg-${var.environment}"
  }
}

7. AWS CLI Verification Drill

Validate that AWS has provisioned the network resources according to specifications:

terminal — AWS CLI verification commands
BASH
# Check VPC State is 'available'
aws ec2 describe-vpcs \
  --vpc-ids $(terraform output -raw vpc_id) \
  --query "Vpcs[0].State" --output text
# Expected: available

# Inspect Route Table for 0.0.0.0/0 -> igw route
aws ec2 describe-route-tables \
  --filters "Name=vpc-id,Values=$(terraform output -raw vpc_id)" \
  --query "RouteTables[0].Routes[?DestinationCidrBlock=='0.0.0.0/0']" \
  --output table

# Verify Security Group Ingress rules
aws ec2 describe-security-groups \
  --group-ids $(terraform output -raw security_group_id) \
  --query "SecurityGroups[0].IpPermissions[*].[FromPort,ToPort,IpRanges[0].CidrIp]" \
  --output table

8. Production Troubleshooting Matrix

Error / Symptom Root Cause Remediation Procedure
UnauthorizedOperation during plan/apply IAM credentials lack permissions for EC2 VPC actions. Attach an IAM policy granting ec2:CreateVpc, ec2:CreateSubnet, and ec2:CreateSecurityGroup.
Connection timeout when curling app ISP rotated your dynamic public IPv4 address. Re-run curl -s https://checkip.amazonaws.com, update my_ip in terraform.tfvars, and run terraform apply.
Subnet unreachable from internet Missing Route Table association or no IGW route. Verify aws_route_table_association and ensure aws_route_table.public defines route 0.0.0.0/0 -> igw.id.
Postgres port 5432 exposed to web Inadvertent ingress rule added in Security Group. Audit SG ingress rules. PostgreSQL must NEVER have a public ingress rule; only containers inside the Docker bridge talk to port 5432.

9. Production Hardening Checklist

  • [x] Custom VPC created (10.0.0.0/16); default AWS VPC avoided.
  • [x] Explicit DNS resolution enabled (enable_dns_hostnames = true, enable_dns_support = true).
  • [x] Public subnet mapped to deterministic AZ (us-east-1a).
  • [x] Internet gateway attached and associated with public route table.
  • [x] Ports 22, 3000, 3001 locked strictly to administrator IP (/32).
  • [x] Port 5432 (Postgres) completely blocked from internet ingress.
  • [x] Terraform provider versions locked in versions.tf.
