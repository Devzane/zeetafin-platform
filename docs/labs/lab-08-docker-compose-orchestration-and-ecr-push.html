Persistence Mandate Containers are ephemeral by definition. The database container can be destroyed and recreated instantly—all ACID state lives exclusively in the persistent volume mapped to EBS.

1. Lab Objectives

Running multi-tier enterprise applications with manual docker run commands results in broken dependency orders, race conditions during database schema migrations, and accidental data destruction. In this lab, we codify our runtime stack with Docker Compose.

You will achieve the following milestones:

  • Codify the 3-Tier Production Stack: Define PostgreSQL 16 Alpine, NestJS API, and Next.js UI in deploy/docker-compose.prod.yml.
  • Eliminate Database Race Conditions: Enforce condition: service_healthy on PostgreSQL using pg_isready so NestJS never attempts TypeORM migrations on an unready database.
  • Guarantee ACID State Persistence: Bind PostgreSQL data to the named volume zeetafin_prod_pgdata on encrypted gp3 block storage.
  • Isolate Database Traffic: Join all containers to zeetafin-prod-net and block PostgreSQL port 5432 from exposing to the host machine.

2. Compose Orchestration Model

Deterministic Chaining

1. Postgres Starts: Runs pg_isready probe every 5s.
2. Backend Waits: Will NOT start until Postgres passes 3 consecutive healthy checks.
3. Frontend Waits: Will NOT start until Backend passes curl /api/health.

3. Production Compose Specification (deploy/docker-compose.prod.yml)

deploy/docker-compose.prod.yml
YAML
services:
  # ============================================================================
  # DATABASE SERVICE (PostgreSQL 16 Alpine)
  # ============================================================================
  db:
    image: postgres:16-alpine
    container_name: zeetafin-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${DB_USERNAME:-zeetafin_user}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: ${DB_DATABASE:-zeetafin_db}
    volumes:
      - zeetafin_prod_pgdata:/var/lib/postgresql/data
    networks:
      - zeetafin-prod-net
    expose:
      - "5432"  # Internal to bridge network only; NO host binding
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USERNAME:-zeetafin_user} -d ${DB_DATABASE:-zeetafin_db}"]
      interval: 5s
      timeout: 5s
      retries: 5
      start_period: 10s

  # ============================================================================
  # BACKEND SERVICE (NestJS 10 REST API)
  # ============================================================================
  backend:
    image: ${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/zeetafin-backend:${IMAGE_TAG:-latest}
    container_name: zeetafin-backend
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      NODE_ENV: production
      PORT: 3001
      DB_HOST: db
      DB_PORT: 5432
      DB_USERNAME: ${DB_USERNAME:-zeetafin_user}
      DB_PASSWORD: ${DB_PASSWORD}
      DB_DATABASE: ${DB_DATABASE:-zeetafin_db}
      JWT_SECRET: ${JWT_SECRET}
      JWT_EXPIRATION: ${JWT_EXPIRATION:-86400}
    ports:
      - "3001:3001"
    networks:
      - zeetafin-prod-net
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost:3001/api/health || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 15s

  # ============================================================================
  # FRONTEND SERVICE (Next.js 14 App Router)
  # ============================================================================
  frontend:
    image: ${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/zeetafin-frontend:${IMAGE_TAG:-latest}
    container_name: zeetafin-frontend
    restart: unless-stopped
    depends_on:
      backend:
        condition: service_healthy
    environment:
      NODE_ENV: production
      PORT: 3000
      NEXT_PUBLIC_API_URL: ${NEXT_PUBLIC_API_URL:-http://localhost:3001}
    ports:
      - "3000:3000"
    networks:
      - zeetafin-prod-net
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost:3000 || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 10s

volumes:
  zeetafin_prod_pgdata:
    name: zeetafin_prod_pgdata

networks:
  zeetafin-prod-net:
    name: zeetafin-prod-net
    driver: bridge

4. Database Storage & Persistence Drill

Prove that destroying containers does not destroy PostgreSQL transaction records:

terminal — state persistence validation
BASH
# 1. Start the stack in detached mode
docker compose -f deploy/docker-compose.prod.yml up -d

# 2. Insert test ledger record inside database
docker exec -i zeetafin-db psql -U zeetafin_user -d zeetafin_db <<EOF
CREATE TABLE IF NOT EXISTS test_ledger (id serial PRIMARY KEY, balance numeric);
INSERT INTO test_ledger (balance) VALUES (50000.00);
SELECT * FROM test_ledger;
EOF

# 3. Completely terminate and destroy containers
docker compose -f deploy/docker-compose.prod.yml down

# 4. Re-launch stack
docker compose -f deploy/docker-compose.prod.yml up -d

# 5. Query table to confirm persistence across container teardown
docker exec -i zeetafin-db psql -U zeetafin_user -d zeetafin_db \
  -c "SELECT * FROM test_ledger;"
# Output confirms 50000.00 is intact!

6. Stack Launch & Verification

terminal — probe services via curl
BASH
# 1. Probe Backend Health
curl -s http://localhost:3001/api/health | jq .
# Expected: {"status":"ok","info":{"database":{"status":"up"}}}

# 2. Probe Frontend HTTP 200
curl -I http://localhost:3000
# Expected: HTTP/1.1 200 OK

# 3. Confirm Postgres port 5432 is NOT open on the host machine
nc -zv 127.0.0.1 5432
# Expected: Connection refused (Safe!)

7. Troubleshooting Matrix

Issue Cause Remediation
Backend restarts repeatedly on launch Database connection refused; TypeORM attempted migrations before Postgres socket was ready. Ensure depends_on.db.condition = service_healthy is set and pg_isready check is configured on db.
Postgres data lost after reboot Volume mapped to container directory without named volume definition. Verify volumes: - zeetafin_prod_pgdata:/var/lib/postgresql/data and named volume declaration at bottom of compose file.
502 Bad Gateway or connection timeout between containers Services on separate bridge networks. Explicitly attach all three services to networks: - zeetafin-prod-net.

8. Hardening Checklist

  • [x] Docker Compose v2 native syntax implemented without legacy hyphen format.

  • [x] PostgreSQL state persisted to zeetafin_prod_pgdata named volume.
  • [x] Database port 5432 kept internal; zero public host port exposures.
  • [x] Frontend and backend expose healthcheck probes.
