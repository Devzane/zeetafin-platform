Critical Standalone Gotcha Next.js standalone output contains only dynamic JavaScript handlers. If you omit copying .next/static and public/ into the final image, your web UI will render without CSS, fonts, and images.

1. Lab Objectives

Containerizing a modern Next.js application using standard npm start forces you to copy the entire node_modules directory into production, generating images exceeding 1.5 GB that take minutes to deploy. In this lab, we build an optimized standalone container.

You will achieve the following milestones:

  • Enable Next.js Dependency Tracing: Configure output: 'standalone' in next.config.js to trace and bundle only the exact JavaScript files necessary for production SSR.
  • Overcome the Standalone Static Asset Trap: Properly map .next/static/ and public/ into the standalone directory structure so CSS, fonts, and images load correctly.
  • Optimize Alpine Image Processing: Integrate sharp on Alpine Linux using musl libc compatible bindings.
  • Enforce Isolated User Privileges: Create a dedicated system user and group nextjs:nodejs (UID 1001) and drop all root privileges.

2. How Standalone Output Works

During next build, Next.js inspects all imports across pages, server actions, and API routes. It produces an automated standalone server in .next/standalone/server.js alongside a pruned subset of node_modules containing only what is strictly required to execute.

Massive Reduction

A standard Next.js directory with node_modules weighs ~1.5 GB. The standalone output folder weighs ~45 MB. Coupled with Alpine Linux, the entire container finishes under 135 MB.

3. The Static Asset Architecture Trap

Standalone mode intentionally separates dynamic execution from static assets, assuming static files will be hosted on a CDN (like AWS CloudFront or S3). Because we run in a frugal, self-contained container architecture, the container's built-in server must serve static files directly.

To accomplish this, the Dockerfile must explicitly execute two copy commands:

  1. COPY --from=builder /app/.next/static ./.next/static
  2. COPY --from=builder /app/public ./public

4. Next.js Configuration (apps/frontend/next.config.js)

apps/frontend/next.config.js
JAVASCRIPT
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'standalone',
  reactStrictMode: true,
  poweredByHeader: false,
  compress: true,
  images: {
    formats: ['image/avif', 'image/webp'],
  },
};

module.exports = nextConfig;

5. Multi-Stage Dockerfile (apps/frontend/Dockerfile)

apps/frontend/Dockerfile
DOCKERFILE
# ==============================================================================
# STAGE 1: Dependencies
# ==============================================================================
FROM node:20-alpine AS deps
WORKDIR /app
RUN apk add --no-cache libc6-compat
COPY package*.json ./
RUN npm ci

# ==============================================================================
# STAGE 2: Standalone Builder
# ==============================================================================
FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Disable Next.js telemetry during container build
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

# ==============================================================================
# STAGE 3: Minimal Production Runner
# ==============================================================================
FROM node:20-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

# Create unprivileged system user & group (UID 1001)
RUN addgroup --system --gid 1001 nodejs && \
    adduser --system --uid 1001 nextjs

# Copy static assets and public directory
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000

CMD ["node", "server.js"]

7. Troubleshooting Matrix

Symptom Root Cause Solution
UI renders unstyled without CSS or fonts .next/static omitted from copy instructions in runner stage. Add COPY --from=builder /app/.next/static ./.next/static to the Dockerfile.
Container binds to 127.0.0.1; inaccessible from host Next.js defaults to localhost in container environment. Set ENV HOSTNAME="0.0.0.0" in the Dockerfile.
sharp: Missing libvips on Alpine Alpine uses musl libc; pre-built sharp binaries require glibc compatibility. Install libc6-compat in the base Alpine stage.

8. Hardening Checklist

  • [x] output: 'standalone' enabled in next.config.js.
  • [x] Telemetry completely disabled (ENV NEXT_TELEMETRY_DISABLED=1).
  • [x] Both .next/static and public/ copied into the standalone runner stage.
  • [x] ENV HOSTNAME="0.0.0.0" set to allow container port forwarding.
  • [x] Non-root user nextjs (UID 1001) owns files and executes server.js.
  • [x] Final shipping image footprint verified under 140 MB.
