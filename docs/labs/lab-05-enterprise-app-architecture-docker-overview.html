1. Lab Objectives

Containerizing enterprise software without understanding its architectural and domain constraints leads to bloated images, security vulnerabilities, and database split-brain disasters. In this lab, we unpack the application topology of ZeetaFin.

You will achieve the following milestones:

  • Master 3-Tier Enterprise Decoupling: Understand the interaction contracts between Next.js (SSR UI), NestJS (TypeORM REST API), and PostgreSQL (ACID Ledger).
  • Analyze Double-Entry Accounting Requirements: Learn why financial transactions cannot tolerate eventual consistency, justifying a modular monolith over distributed microservices.
  • Define Multi-Stage Image Optimization Principles: Establish rules that strip build compilers, header files, and devDependencies from final shipping containers.
  • Enforce Defense-in-Depth Container Security: Mandate non-root execution (UID 1000/1001) and forbid host binding of the database port (5432).

4. The Financial Ledger Domain: Why a Monolith?

In financial engineering, the fundamental invariant is the double-entry bookkeeping identity:

$$\Large \sum \text{Debits} \equiv \sum \text{Credits}$$

If account A transfers $1,000 to account B, the debit to account A and the credit to account B must commit simultaneously within a single database transaction isolation level (Serializable or Read Committed). If split across distributed microservices via HTTP or Kafka, network partitions can cause one half to fail, creating catastrophic financial drift.

Architectural Decision: Domain Monolith

By packaging accounts, transactions, and invoicing into a unified NestJS domain monolith backed by PostgreSQL, we retain full ACID transactional integrity while maintaining clean modular code boundaries inside apps/backend/src/.

6. Port & Bridge Isolation Model

The 5432 Ingress Rule

In deploy/docker-compose.prod.yml, the PostgreSQL service deliberately omits a ports: block and uses only expose: - "5432". This prevents the Docker daemon from inserting iptables NAT rules forwarding host traffic into the database. Only containers joined to the zeetafin-prod-net bridge can connect.

8. Architectural Checklist

  • [x] 3-tier architecture defined: Next.js UI (3000) → NestJS API (3001) → PostgreSQL (5432).
  • [x] Modular monolith pattern chosen to guarantee ACID double-entry ledger balance constraints.
  • [x] Multi-stage build pattern defined across all services to isolate compilers from runtimes.
  • [x] Non-root execution policy enforced: UID 1000 for NestJS, UID 1001 for Next.js.
  • [x] Port 5432 forbidden from external host binding, confined strictly to internal bridge network.
